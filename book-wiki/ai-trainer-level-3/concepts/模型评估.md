# 模型评估

- **来源章节**: 2.2.1
- **定义**: 使用测试集数据评估模型的预测性能，通过多个指标（精确率、召回率、F1-score、准确率）量化模型质量
- **核心方法**:
  ```python
  from sklearn.metrics import classification_report
  
  # 1. 生成详细分类报告
  report = classification_report(y_test, y_pred, zero_division=1)
  print(report)
  
  # 2. 计算总体准确率
  accuracy = model.score(X_test, y_test)
  print(f"模型准确率: {accuracy:.2f}")
  ```
- **分类报告核心指标**:
  | 指标 | 英文 | 含义 | 计算公式 | 业务解读 |
  |---|---|---|---|---|
  | **精确率** | precision | 预测为正类的样本中，真正是正类的比例 | TP / (TP + FP) | 「我说你违约，我说对的概率」 |
  | **召回率** | recall | 真正是正类的样本中，被预测出来的比例 | TP / (TP + FN) | 「真正违约的人，我抓到几个」 |
  | **F1-score** | f1-score | 精确率和召回率的调和平均 | 2 × (P × R) / (P + R) | 平衡指标，综合评价 |
  | **support** | support | 该类别在测试集的真实样本数 | — | 样本量（不是性能指标） |
- **混淆矩阵术语**（理解指标的基础）:
  ```
  实际 \ 预测 │  预测 0  │  预测 1
  ───────────┼─────────┼─────────
  真实 0     │  TN ✅  │  FP ❌ 
  真实 1     │  FN ❌  │  TP ✅
  
  - TP (True Positive): 真拖欠，预测拖欠 ✅
  - TN (True Negative): 不拖欠，预测不拖欠 ✅
  - FP (False Positive): 不拖欠，预测拖欠 ❌（误杀好客户，I型错误）
  - FN (False Negative): 真拖欠，预测不拖欠 ❌（漏检坏客户，II型错误）
  ```
- **分类报告示例**（2.2.1 典型输出）:
  ```
                precision  recall  f1-score  support
  
           0       0.93      0.98      0.95      850
           1       0.67      0.35      0.46      150
  
    accuracy                           0.91     1000
   macro avg       0.80      0.67      0.71     1000
  weighted avg     0.89      0.91      0.89     1000
  ```
  **解读**：
  - **类别 0（正常客户）**: 精确率 93%，召回率 98%，表现优秀
  - **类别 1（违约客户）**: 精确率 67%，召回率 35%，**严重问题！**
    - 召回率 35% 意味着 65% 的违约客户被漏检（预测为 0）
    - 精确率 67% 说明预测为违约的客户中，有 33% 是误判
  - **准确率 91%** 看似很高，但掩盖了少数类预测失败的问题
- **业务场景下的指标权衡**:
  | 场景 | 优先指标 | 理由 |
  |---|---|---|
  | **信用评分** | 召回率（抓违约） | 放过一个坏客户（FN）→ 银行损失真金白银；误伤好客户（FP）→ 只是少赚利息 |
  | **垃圾邮件** | 精确率（少误判） | 正常邮件进垃圾箱（FP）→ 用户错过重要信息；漏掉垃圾邮件（FN）→ 只是多看一封广告 |
  | **癌症筛查** | 召回率（少漏检） | 漏检患者（FN）→ 延误治疗，致命；误判健康人（FP）→ 复查后排除，可接受 |
  | **推荐系统** | F1-score（平衡） | 既要推荐准（precision），又要覆盖全（recall） |
- **准确率的陷阱**（类别不平衡时）:
  ```python
  # 场景：1000 个客户，只有 50 个违约（5%）
  # 策略 1：全预测为 0（不违约）
  准确率 = 950 / 1000 = 95%  ← 看起来很高！
  召回率(1) = 0 / 50 = 0%     ← 一个违约都没抓到！
  
  # 策略 2：用 SMOTE 平衡后训练
  准确率 = 850 / 1000 = 85%  ← 下降了
  召回率(1) = 35 / 50 = 70%  ← 但能抓到 70% 的违约，业务价值更高！
  ```
  **结论**：类别不平衡时，**准确率不可信**，要看**召回率**或 **F1-score**。
- **zero_division=1 参数**:
  ```python
  classification_report(y_test, y_pred, zero_division=1)
  ```
  - **作用**：避免除以 0 的警告（某类别预测数为 0 时）
  - **默认**：`zero_division='warn'`（打印警告）
  - **设为 1**：出现除以 0 时，指标设为 1（考试要求，避免输出警告信息）
- **模型评估流程**:
  ```python
  # 1. 训练模型
  model.fit(X_train, y_train)
  
  # 2. 预测测试集
  y_pred = model.predict(X_test)
  
  # 3. 生成分类报告
  report = classification_report(y_test, y_pred, zero_division=1)
  print(report)
  
  # 4. 计算准确率
  accuracy = model.score(X_test, y_test)
  print(f"准确率: {accuracy:.2f}")
  
  # 5. 保存报告到文件（考试要求）
  with open('2.2.1_report.txt', 'w') as file:
      file.write(report)
  ```
- **答题卷填写示例**（2.2.1 要求）:
  ```
  针对Logistic模型
  1、模型性能
  
                precision  recall  f1-score  support
  0（没有严重逾期）   0.93     0.98     0.95      850
  1（有严重逾期）     0.67     0.35     0.46      150
  
  2、错误分析
  - 类别 1 召回率仅 0.35，意味着 65% 的违约客户被漏检
  - 原因：训练数据中违约样本占比过低（约 15%），模型偏向多数类
  
  3、改进建议
  - 使用 SMOTE 过采样平衡训练集
  - 调整 class_weight='balanced' 参数给少数类更高权重
  - 根据业务需求调整阈值（如概率 >0.3 即判为高风险）
  ```
- **常见问题**:
  **Q1: 准确率 91% 但召回率只有 35%，模型好还是坏？**
  A: **坏模型**。准确率高是因为数据不平衡（85% 都是类别 0），模型「猜大头」。召回率低说明业务关键指标失败。
  
  **Q2: 精确率和召回率能同时提高吗？**
  A: **很难**。两者通常互斥（翘翘板效应）：
  - 提高召回率（多抓违约）→ 误判增多 → 精确率下降
  - 提高精确率（少误判）→ 漏检增多 → 召回率下降
  解决方法：优化模型（更多数据、更好特征、更强算法）或根据业务设置阈值。
  
  **Q3: F1-score 什么时候用？**
  A: 当精确率和召回率都重要时（如搜索引擎：既要结果准，又要覆盖全）。F1 是两者的调和平均，偏向较低的那个指标。
- **易错点**:
  - ❌ 只看准确率，忽略召回率 → 类别不平衡时准确率失真
  - ❌ 用训练集评估 → `model.score(X_train, y_train)` 结果虚高
  - ❌ 忘记 `zero_division=1` → 输出警告信息，考试可能扣分
  - ✅ **永远用测试集评估**，关注业务关键指标（信用评分看召回率）
