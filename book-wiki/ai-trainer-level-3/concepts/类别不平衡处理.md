# 类别不平衡处理

- **来源章节**: 2.2.1
- **定义**: 当训练数据中某类样本极少（如违约客户 <10%），模型倾向预测多数类，导致少数类召回率极低。通过 SMOTE 过采样等技术平衡数据，提升少数类预测性能
- **核心方法**:
  ```python
  from imblearn.over_sampling import SMOTE
  
  # 1. 创建 SMOTE 过采样器
  smote = SMOTE(random_state=42)
  
  # 2. 对训练集过采样（⚠️ 只对训练集，不动测试集！）
  X_resampled, y_resampled = smote.fit_resample(X_train, y_train)
  
  # 3. 用新数据重新训练
  model.fit(X_resampled, y_resampled)
  
  # 4. 预测测试集（测试集不变）
  y_pred = model.predict(X_test)
  ```
- **问题诊断**（什么时候需要处理不平衡？）:
  | 数据特征 | 模型表现 | 是否需要处理 |
  |---|---|---|
  | 多数类 : 少数类 = 9:1 | 准确率 90%，召回率(少数类) <0.3 | ✅ **必须处理** |
  | 多数类 : 少数类 = 7:3 | 准确率 80%，召回率(少数类) 0.6 | ⚠️ 视情况处理 |
  | 多数类 : 少数类 = 5:5 | 两类召回率都 >0.7 | ❌ 数据平衡，无需处理 |
  
  **典型症状**：
  - 准确率很高（>90%），但少数类召回率极低（<0.3）
  - 模型「猜大头」：全预测为多数类，准确率 = 多数类占比
- **SMOTE 原理**（Synthetic Minority Over-sampling Technique）:
  ```
  1. 找到少数类样本 A 的 k 个最近邻（默认 k=5）
  2. 从邻居中随机选一个 B
  3. 在 A 和 B 的连线上随机生成新样本：
     new_sample = A + rand(0, 1) × (B - A)
  4. 重复直到少数类数量 ≈ 多数类数量
  ```
  **示意图**（文字版）:
  ```
  原始数据：
  多数类（0）: 900 个样本  ●●●●●●●●●
  少数类（1）: 100 个样本  ○○
  
  SMOTE 后：
  多数类（0）: 900 个样本  ●●●●●●●●●
  少数类（1）: 900 个样本  ○○○○○○○○○（新增 800 个合成样本）
  ```
- **为什么只对训练集 SMOTE？**（核心考点）:
  ```python
  # ✅ 正确做法
  X_resampled, y_resampled = smote.fit_resample(X_train, y_train)
  model.fit(X_resampled, y_resampled)  # 训练集平衡
  y_pred = model.predict(X_test)       # 测试集不变
  
  # ❌ 错误做法
  X_all_resampled, y_all_resampled = smote.fit_resample(X, y)
  # 然后划分训练测试集 → 合成样本可能泄露到测试集 → 评估失真！
  ```
  **理由**：
  - **训练集**：用于模型学习，平衡后让模型「平等对待」两类样本
  - **测试集**：模拟真实场景，真实场景中违约率就是低（<10%），必须保持原始分布
  - **如果测试集也 SMOTE**：违约率变 50%，评估就失去意义（真实世界不是 50%）
- **效果对比**（2.2.1 典型结果）:
  | 阶段 | 准确率 | precision(1) | recall(1) | f1-score(1) |
  |---|---|---|---|---|
  | SMOTE 前 | 0.93 | 0.67 | 0.35 | 0.46 |
  | SMOTE 后 | 0.85 | 0.58 | 0.68 | 0.63 |
  
  **关键变化**：
  - 准确率下降（93% → 85%）—— **正常现象！** 不再「猜大头」了
  - 召回率提升（35% → 68%）—— **核心目标！** 抓到更多违约客户
  - F1-score 提升（0.46 → 0.63）—— 综合性能变好
- **其他不平衡处理方法**（拓展，考试不涉及）:
  | 方法 | 原理 | 优劣 |
  |---|---|---|
  | **SMOTE** | 为少数类生成合成样本 | ✅ 效果好 ❌ 可能引入噪声 |
  | **欠采样** | 删除多数类样本 | ✅ 简单快速 ❌ 损失大量数据 |
  | **class_weight** | 给少数类更高权重 | ✅ 不改数据 ❌ 效果不如 SMOTE |
  | **集成方法** | BalancedRandomForest | ✅ 自动平衡 ❌ 换算法 |
  
  **考试只用 SMOTE**，其他了解即可。
- **完整对比代码**:
  ```python
  # === 第一轮：未处理不平衡 ===
  model = LogisticRegression(max_iter=1000)
  model.fit(X_train, y_train)
  y_pred = model.predict(X_test)
  
  print("未处理前：")
  print(classification_report(y_test, y_pred))
  # 结果：准确率 93%，召回率(1) 0.35
  
  # === 第二轮：SMOTE 处理 ===
  smote = SMOTE(random_state=42)
  X_resampled, y_resampled = smote.fit_resample(X_train, y_train)
  
  model.fit(X_resampled, y_resampled)
  y_pred_resampled = model.predict(X_test)
  
  print("SMOTE 后：")
  print(classification_report(y_test, y_pred_resampled))
  # 结果：准确率 85%，召回率(1) 0.68
  ```
- **random_state=42 的作用**:
  ```python
  smote = SMOTE(random_state=42)
  ```
  - **固定随机种子**：保证每次生成的合成样本位置相同
  - **考试必加**：否则每次运行结果不同，评分时对不上答案
- **常见问题**:
  **Q1: SMOTE 后准确率下降，是不是失败了？**
  A: **不是失败，是正常现象**。准确率下降是因为不再「猜大头」了；关键看少数类召回率是否提升（这才是业务目标）。
  
  **Q2: 能否直接调整 class_weight 而不用 SMOTE？**
  A: 可以尝试，但效果通常不如 SMOTE：
  ```python
  model = LogisticRegression(max_iter=1000, class_weight='balanced')
  model.fit(X_train, y_train)
  ```
  `class_weight='balanced'` 自动给少数类更高权重，但不改变数据分布。
  
  **Q3: 为什么不用欠采样（删除多数类样本）？**
  A: 欠采样会丢失大量信息。例如 900 个正常客户随机删到 100 个，损失 800 个样本的特征信息。SMOTE 不损失数据，只增加少数类。
  
  **Q4: SMOTE 会过拟合吗？**
  A: 可能。合成样本是「造」出来的，如果 k 近邻选不好，可能生成噪声。解决方法：
  - 调整 `k_neighbors` 参数（默认 5）
  - 尝试 SMOTE 变体（如 BorderlineSMOTE、ADASYN）
- **易错点**:
  - ❌ 对整个数据集 SMOTE，再划分训练测试集 → 数据泄露！
  - ❌ 对测试集也 SMOTE → 评估失真！
  - ❌ SMOTE 前后用不同的测试集 → 结果不可比
  - ✅ 固定流程：划分数据集 → 只对训练集 SMOTE → 训练 → 用原始测试集评估
- **考试注意事项**:
  - SMOTE 后的结果文件名带 `_xg` 后缀（如 `2.2.1_results_xg.txt`，表示「修改后」）
  - 答题卷要对比 SMOTE 前后的性能变化，说明改进效果
  - `random_state=42` 必加，保证结果可复现
