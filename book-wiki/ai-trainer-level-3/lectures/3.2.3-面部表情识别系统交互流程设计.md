## 二、先识别原题中的环境兼容问题

原题预处理函数固定使用：

```python
img = img.resize((64, 64), Image.ANTIALIAS)
```

Pillow 10 已移除 `Image.ANTIALIAS`，对应的新名称为 `Image.Resampling.LANCZOS`。当前练习环境 Pillow 12.3.0 没有旧名称，所以可能在进入模型预测之前报 `AttributeError`，这不是填空答案错误。

在允许增加独立环境准备单元格的学习场景，可先执行下面的兼容准备，随后仍运行原题固定代码：

```python
from PIL import Image

if not hasattr(Image, 'ANTIALIAS'):
    Image.ANTIALIAS = Image.Resampling.LANCZOS
```

这只是给当前 Python 进程补充旧名称，不会修改 Pillow 安装文件；重启内核后需要重新准备。它不是题目中的填空答案。正式考试如不允许增加准备代码，应先确认考试环境兼容，不要将这段代码硬塞进填空或擅改原题预处理函数。

## 三、八种表情与字典方向

题目给出的映射方向是“名称 → 数字”：

```python
emotion_table = {
    'neutral': 0, 'happiness': 1, 'surprise': 2, 'sadness': 3,
    'anger': 4, 'disgust': 5, 'fear': 6, 'contempt': 7
}
```

对应中文可理解为中性、快乐、惊讶、悲伤、愤怒、厌恶、恐惧、轻蔑。顺序必须与题目一致，不能按自己的习惯重新排列。

模型输出的 `predicted_label` 是数字，需要反过来查名称：

```python
predicted_label = np.argmax(ort_outs[0])
predicted_emotion = {value: name for name, value in emotion_table.items()}[predicted_label]
```

例如模型返回 2，反向字典会得到 `'surprise'`。直接写 `emotion_table[2]` 不行，因为原字典的键是英文名称，而不是整数。

原题最后一空后面已经有 `[predicted_label]`，该空只需填反向字典表达式，不要重复填写索引。

## 四、推理接口和数组形状

```python
ort_session = ort.InferenceSession('emotion-ferplus.onnx')
input_data = preprocess('img_test.png')
ort_inputs = {ort_session.get_inputs()[0].name: input_data}
ort_outs = ort_session.run(None, ort_inputs)
```

- `preprocess` 是原题给出的函数，传入的是文件路径。
- 灰度数组先为 `(64, 64)`，经两次扩展成为 `(1, 1, 64, 64)`。
- `run` 第一个参数 `None` 表示返回全部输出；第二个参数是“输入名 → 输入数组”的字典。
- `ort_outs[0]` 是第一个输出张量；`np.argmax` 找最大分数的索引，不是概率数值。

原题用 `assert` 检查最终输入形状。如果它报错，先检查形状处理，而不是直接删除检查。这里也没有要求额外除以 255 或使用 RGB 均值。

以下参考只补原题填空，保留了原题的 `Image.ANTIALIAS`。在新 Pillow 环境运行前，先处理上文所述兼容问题。

```python
# 导入必要的库
import numpy as np
from PIL import Image
import onnxruntime as ort


# 定义预处理函数，用于将图片转换为模型所需的输入格式
def preprocess(image_path):
    input_shape = (1, 1, 64, 64)    # 模型输入期望的形状，这里是 (N, C, H, W)，N=batch size, C=channels, H=height, W=width
    img = Image.open(image_path).convert('L')    # 打开图像文件并将其转换为灰度图  1分
    img = img.resize((64, 64), Image.ANTIALIAS)    # 调整图像大小到模型输入所需的尺寸
    img_data = np.array(img, dtype=np.float32)    # 将PIL图像对象转换为numpy数组，并确保数据类型是float32
    # 调整数组的形状以匹配模型输入的形状
    img_data = np.expand_dims(img_data, axis=0)  # 添加 batch 维度
    img_data = np.expand_dims(img_data, axis=1)  # 添加 channel 维度
    assert img_data.shape == input_shape, f"Expected shape {input_shape}, but got {img_data.shape}"    # 确保最终的形状与模型输入要求的形状一致
    return img_data    # 返回预处理后的图像数据


# 定义情感类别与数字标签的映射表 3分
emotion_table = {'neutral': 0, 'happiness': 1, 'surprise': 2, 'sadness': 3, 'anger': 4, 'disgust': 5, 'fear': 6, 'contempt': 7}


# 加载模型 3分
ort_session = ort.InferenceSession('emotion-ferplus.onnx')    # 使用onnxruntime创建一个会话，用于加载并运行模型


# 加载本地图片并进行预处理 3分
input_data = preprocess('img_test.png')


# 准备输入数据，确保其符合模型输入的要求
ort_inputs = {ort_session.get_inputs()[0].name: input_data}    # ort_session.get_inputs()[0].name 是获取模型的第一个输入的名字


# 运行模型，进行预测 3分
ort_outs = ort_session.run(None, ort_inputs)


# 解码模型输出，找到预测概率最高的情感类别 3分
predicted_label = np.argmax(ort_outs[0])


# 根据预测的标签找到对应的情感名称 3分
predicted_emotion = {value: name for name, value in emotion_table.items()}[predicted_label]


# 输出预测的情感
print(f"Predicted emotion: {predicted_emotion}")
```

## 六、结果核验和交互方案

使用本地模型和图片，在完成兼容准备后，实测输出：

```text
Predicted emotion: surprise
```

模型给出的是图片的表情分类标签，不应直接当作被摄者真实心理状态的结论。

答题卷可从以下方面组织至少三条可执行的交互措施：

- 拍摄或上传前获得用户同意，说明图片用途，提供删除入口。
- 显示原图预览，提示人脸清晰、光线适当、无遮挡，并允许重拍。
- 在原图旁显示识别标签，允许用户确认或更正，不能强制接受结果。
- 对不清晰、多人或不适合识别的图片提示重新选择或转人工判断。
- 不把识别结果自动扩展成医疗诊断、身份判断等超出本题的结论。
